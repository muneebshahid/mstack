# Skill Eval report

## Target and claim

Name the existing skill, the behavior evaluated, the selected fidelity profile, every temporary model or effort substitution, and the proposed revision when one exists. State explicitly when an execution smoke test does not establish production-model output quality.

## Scenarios and rubric

List each organic scenario, the criteria registered before running, and whether it tested activation or force-loaded execution.

## Structural findings

Report validation, links, resources, scripts, description, and progressive-disclosure issues separately from model behavior.

## Observed behavior

For each neutral run label, record the outcome, material trace and artifact evidence, mutations, capability failures, and unexercised branches.

## Comparison

When a revision exists, state material improvements, regressions, ties, and differences too small or noisy to attribute. Omit this section for a single-skill evaluation.

## Judge and parent judgment

Summarize the blinded judge's verdict, then state where the parent confirmed, corrected, or rejected it and why.

## Recommendation

For a revision, choose Promote, Revise, Reject, or Inconclusive. For a current-skill evaluation, state whether the skill works as claimed and list issues in priority order.

## Reproduction and cleanup

Record the model configuration, complete proposed diff when present, scenario and fixture identity, relevant hashes and trace excerpts, removed temporary artifacts, and anything needed for another run. List evidence paths only when they were intentionally retained; never present a deleted temporary path as retained evidence.
