# Evidence

Use this menu to choose sources as the investigation develops. Search within the relevant project, service, and time range. Connected tools make a source available; they do not make it relevant.

| Source | When it helps |
| --- | --- |
| Code, tests, configuration, schemas | Current behavior, contracts, relationships, and ownership. |
| Git history, blame, diffs, PRs and reviews | When behavior changed, regressions, and recorded reasons for a change. |
| Logbook and agent work records | What agents did, what was accepted or rejected, why, and what remains unverified. |
| Linear or other issue trackers | Requirements, acceptance criteria, bug reports, and scope decisions. |
| Project docs, ADRs, Notion, or linked design documents | Design constraints, alternatives, and decisions spanning multiple changes. |
| Relevant Slack threads or other project discussions | Clarifications and rationale missing from tickets or commits. |
| Cloudflare or other service logs, traces, metrics, and error reports | What happened in production, when, and under which conditions. |
| Deployment history and incident reports | Release-specific behavior, configuration changes, outages, and attempted fixes. |

Follow links between sources when they could resolve the question. Use available connectors or local tools and their guidance; an installed skill alone does not establish access. If a source is unavailable, continue with other evidence and report any resulting uncertainty.

Check a record's status and date: proposals, rejected approaches, and investigation recommendations may never have been implemented. Separate documented reasons from your own inferences. A search with no relevant results does not prove something never happened; distinguish that outcome from a search you could not run.
